# MoonBit 生态项目申报书（框架稿）

> 项目暂定名：**moonl10n —— 纯 MoonBit 的 CLDR 本地化格式化内核**
> 申报方向：应用开发与内容处理 / 语言与开发工具（跨方向，建议选前者）
> 文档状态：框架稿 v0.1，`【待补充】` 为后续填写位置

## 0. 一页摘要（评审最先看的部分）

**一句话定位**：为 MoonBit 提供一套不依赖宿主 `Intl`、在所有后端输出一致的 CLDR 本地化格式化内核。

**要解决的问题**：MoonBit 现有 i18n 方案把数字、日期、货币、复数等格式化能力外包给 JavaScript 宿主的 `Intl`。一旦编译到 WASM-GC 之外的纯 WASM、Native 或嵌入式环境，这些能力全部失效；生态中也缺少可被图表、文档、UI、后端服务共用的底层格式化库。

**交付物**：可发布的 `mooncakes.io` 包组 + CLDR 数据裁剪工具链 + 官方 conformance 测试 + WASM playground 演示。

**核心指标**（目标值待定稿时确认）：

- CLDR 官方 conformance：numbers / dates / plural 三类用例通过率 `【待补充：目标 ≥ 99%】`
- 与 JS `Intl`、ICU4X 的差分测试：抽样用例零不一致（除已声明差异项）
- 后端一致性：WASM-GC / JS / Native 三端输出逐字节一致
- 包体积：中英双语核心数据 `【待补充：目标 ≤ 200 KB】`

**三个申报亮点**：

1. **补的是真空层**：生态里有消息目录（MF2）、有排序（UCA）、有 Unicode 规范化，唯独缺"规则数据 → 本地化字符串"这一层。
2. **正确性可量化**：直接吃 CLDR 官方测试数据，评审不需要相信自述，可以看通过率。
3. **天然可复用**：图表轴标签、文档排版、UI 组件、日志与账单都依赖它，属于底座型能力。

## 2. 背景与生态缺口

### 2.1 MoonBit 生态现状

- 生态已进入"抢位"阶段：GitHub 上与 MoonBit 相关的仓库约 `【待补充：2391】` 个，近期活跃项目数百个，覆盖解析器、数据库、图形、音视频、网络协议等方向。
- 应用层与内容处理方向已有 `rabbita`、`proton`、`moui`、各类图表与文档库，但**本地化基础设施仍然缺位**。
- 现有相关项目：
  - `lampclaw/i18n`：Unicode MF2 消息目录 + 代码生成，格式化依赖宿主 `Intl`。
  - `CaptainK-65/moon-collate`：UCA/DUCET 排序。
  - `Orion-XX/moonbit-unicode`：NFC/NFD 规范化与 UAX #29 字素切分。
  - `CCllff-jpg/cldr-conformance`：CLDR 一致性度量工具（度量而非实现）。

### 2.2 缺口的具体表现

1. 纯 WASM / Native 无 `Intl`，现有方案直接失去格式化能力。
2. 数字分组、货币符号位置、紧凑记数（1.2万 / 1.2M）、百分比、会计格式无统一实现。
3. 日期骨架（skeleton）、区间格式、相对时间（3 天前）、复数与序数规则缺失。
4. 各库各自硬编码格式，跨库输出不一致，无法复用。

### 2.3 为什么是现在

- MoonBit 正在从"能跑"走向"能做产品"，Native 与 WASM-GC 后端逐步可用，宿主 `Intl` 的兜底假设不再成立。
- CLDR 数据与官方测试集已稳定发布，具备工程化落地条件。
- 生态已有排序、规范化、消息目录，缺的正是中间那层格式化内核，边际成本最低、协同收益最大。

## 3. 项目目标与范围

### 3.1 总目标

交付一套**纯函数、零 IO、零 FFI** 的本地化格式化内核：输入 `(locale, 值, 选项)`，输出符合 CLDR 的字符串；同一份代码在 WASM-GC / JS / Native 三端输出一致。

### 3.2 明确不做（边界）

- 不做翻译工作流、不做消息目录格式（MF2 已有实现，保持互补）。
- 不做 ICU 全量能力（不做断词、转写、全文排序的全部语言变体）。
- 不做时区数据库的完整打包（首版只做 UTC 偏移与可选 tzdata 适配层）。
- 不做非公历日历（首版仅 Gregorian，其他日历列为扩展）。
- 不绑定任何 UI 框架。

### 3.3 交付物清单

| 交付物 | 说明 | 状态 |
| --- | --- | --- |
| `moonl10n-core` | Locale 解析、回退链、选项模型、错误类型 | `【待补充】` |
| `moonl10n-number` | 数字、货币、百分比、紧凑记数、会计格式 | `【待补充】` |

## 4. 技术方案

### 4.1 总体架构

```text
CLDR XML/JSON 源数据
        │
        ▼
   cldr-gen（裁剪 / 校验 / 代码生成）
        │
        ▼
 moonl10n-data-<locale>  ──┐
        │                  │
        ▼                  ▼
  moonl10n-core  ◄──  number / datetime / plural / units
        │
        ▼
   公开 API（纯函数）
        │
        ├── WASM-GC / JS / Native
        └── Playground / 下游库
```

### 4.2 核心模块设计

#### 4.2.1 CLDR 数据管线

- 输入：CLDR `cldr-numbers-full`、`cldr-dates-full`、`cldr-core` 的 JSON 发布物。
- 处理：按 locale 闭包裁剪、去重、压缩、稳定排序，生成可复现产物（记录源版本与哈希）。
- 输出：MoonBit 可直接消费的常量表 / 二进制块，附生成时间与版本号。
- 关键点：**数据与逻辑分离**，运行时不做 JSON 解析，避免体积与性能损耗。

#### 4.2.2 Locale 解析与回退

- BCP 47 解析、`-u-` 扩展、likely subtags。
- 回退链：`zh-Hant-TW → zh-Hant → zh → root`。
- 语言/地区/书写系统匹配策略与"最佳可用 locale"选择。

#### 4.2.3 数字与货币

- 模式解析（`#,##0.###`）、分组尺寸（含印度式 3;2）、最小/最大小数位。
- 货币符号位置、窄/宽符号、会计负号、百分比缩放。
- 紧凑记数（`1.2万`、`1.2M`）与舍入策略。
- 实现要点：以十进制数字串/定点整数运算为主，避免浮点误差导致的输出不稳定。

#### 4.2.4 日期时间

- 字段符号映射、可用格式（availableFormats）、骨架匹配（skeleton）。
- 日期区间格式与回退规则。
- 相对时间（`3 天前`、`in 2 hours`）与单位复数联动。
- 首版：Gregorian + UTC/固定偏移；tzdata 作为可选适配层。

#### 4.2.5 复数与序数

- CLDR plural rule 语法解析 → 中间表示 → 生成 MoonBit 判定函数（避免运行时解释）。
- 操作数：`n i v w f t c e`；基数与序数两套规则。

#### 4.2.6 单位与列表

- 单位组合、per 形式、单位复数。
- 列表格式化（and / or / unit 三类）。

### 4.3 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 数据处理时机 | 构建期生成 | 运行时零解析、包体积可控 |
| API 风格 | 纯函数 + 不可变选项 | 易测试、易跨端、无隐藏状态 |
| 错误处理 | 显式 `Result` | 与 MoonBit 风格一致，避免抛异常 |
| 数据粒度 | 按 locale 拆包 | 下游可按需依赖，避免全量引入 |
| 与现有库关系 | 互补而非替代 | 排序复用 `moon-collate`，规范化复用 `moonbit-unicode` |

### 4.4 与现有项目的关系

- `lampclaw/i18n`：它解决"消息怎么组织"，本项目解决"值怎么按地区渲染"，可通过适配层组合。
- `moon-collate` / `moonbit-unicode`：作为可选依赖，避免重复实现。
- 图表 / 文档 / UI 库：作为首批集成方，验证复用价值。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| CLDR 数据体积过大 | 包体积、加载时间 | 子集裁剪 + 按需拆包 + 压缩 |
| 时区数据复杂 | 工期、正确性 | 首版只做偏移，tzdata 作为可选层 |
| 非公历日历复杂 | 范围蔓延 | 明确排除，列为后续路线 |
| 与现有 i18n 项目重叠 | 评审质疑重复 | 强调互补定位，提供适配层与联合测试 |
| MoonBit 语言/工具链演进 | 返工 | 锁定版本、CI 多版本矩阵 |
| 浮点导致跨端不一致 | 输出不一致 | 定点/十进制运算，禁用浮点路径 |
